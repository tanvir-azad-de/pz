# 07 — Deployment

## Chosen host: GitHub Pages

GitHub Pages over Vercel for this project: no build step exists (plain HTML/CSS/JS), the repo
is already public, and Pages serves static files from a branch with zero configuration. Vercel
would add an unnecessary layer (project linking, build settings) for no benefit here.

## Required repo setup

1. **`.gitignore`** (added in chunk 0):
```
.DS_Store
*.log
.env
.env.*
```
   Nothing else is generated by this project (no `node_modules`, no build output), so the list
   stays minimal.

2. **`.nojekyll`** (empty file, added in chunk 0): GitHub Pages runs Jekyll by default on
   anything served from a branch, which ignores files/folders starting with `_` and can
   interfere with plain static sites. An empty `.nojekyll` file at the repo root disables that
   processing. Required even though this project has no `_`-prefixed files, as a safety default.

3. **No `index.html` nesting issue**: `index.html` lives at the repo root, so GitHub Pages
   serving from `main` branch root works directly — no `docs/` folder relocation needed (the
   `docs/` folder in this repo is documentation, not the Pages source — don't confuse the two).

## Enabling Pages

1. Repo → **Settings → Pages**.
2. Source: **Deploy from a branch**.
3. Branch: `main`, folder: `/ (root)`.
4. Save. Site will be live at `https://<username>.github.io/<repo>/`.

Since the app uses hash routing (`#/discover`, `#/game/:id`, etc.), no GitHub Pages rewrite
rules or a `404.html` fallback are needed — every route is really just `index.html` with a
different hash, which GitHub Pages serves correctly by default.

## Google Sheet publishing checklist

Before/after deploying, confirm the sheet itself is correctly exposed:

1. Sheet → **Share** → **General access** → **Anyone with the link** → **Viewer**.
2. Create the 6 required tabs with exact lowercase names: `games`, `tasks`, `rewards`,
   `wallet`, `settings`, `content` (see `01-data-model.md` for header rows).
3. Verify each tab with a direct gviz request, e.g.:
   ```
   curl "https://docs.google.com/spreadsheets/d/<SHEET_ID>/gviz/tq?tqx=out:json&sheet=games"
   ```
   Confirm `"status":"ok"` AND that the returned column headers match what you typed — remember
   gviz does not error on a wrong tab name (see `03-sheets-integration.md`), so a visual check
   of the headers in the response is the only reliable confirmation.

## Pre-deploy checklist

- [ ] All 6 Sheet tabs exist, are named exactly as specified, and are publicly viewable.
- [ ] `js/sheets.js` `SHEET_ID` constant matches the live sheet.
- [ ] `data/fallback.json` still mirrors the 6-tab schema (update if columns ever change).
- [x] Brand logo PNGs (PayPal/Amazon/Google Play/Apple) dropped into `assets/icons/` and
      `render.js` (`brandLogo`/`brandLogoWide`) updated to reference them.
- [ ] Open the deployed URL on an actual phone (or responsive mode pinned to a phone width) —
      this app has no desktop layout by design, so desktop testing is not meaningful.
- [ ] Spot-check each of the 8 routes directly by URL (`#/discover`, `#/my-games`, `#/rewards`,
      `#/profile`, `#/game/<a-real-id>`, `#/reward/<a-real-id>`, `#/wallet`, `#/invite`) to
      confirm hash routing + GitHub Pages interact correctly.

## Rollback / iteration

Since there's no build step, every deploy is just a `git push` to `main` — GitHub Pages
redeploys automatically within roughly a minute. No separate release process is needed for a
demo of this scope.

## Decisions

- GitHub Pages, branch `main`, root folder — not Vercel, not a `gh-pages` branch, not a `docs/`
  Pages source (to avoid clashing with this repo's documentation folder of the same name).
- Hash routing chosen specifically because it requires zero GitHub Pages routing configuration.
